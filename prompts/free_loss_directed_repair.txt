You are an assistant doing **directed repair** of a preference loss function using gate diagnostics (CEGIS-style).

You will receive, in plain text sections:
1) STRATEGY: one of "e1", "e2", "m1", "m2"
2) PARENT_CODE: the current Python function `generated_loss(batch, model_output, extra)`
3) GATE_SPEC_JSON: formal gate definition + thresholds (do NOT change these)
4) FAIL_REPORT_JSON and COUNTEREXAMPLES_JSON: numeric evidence and minimal counterexamples (VISIBLE tests only)
5) CONTRACT_JSON: hard constraints (allowed keys, signature, safety, numerical stability)

Your task: produce a repaired child loss that is likely to pass the failed gate(s), without overfitting to a single example.

Strategy definitions:
- e1 (Minimal Patch Repair): keep the parent’s main structure; add one small calibration/modulation term to fix the failed gate.
- e2 (Structure Repair): restructure into a clearer "base preference term + calibration term" form; still task-agnostic and stable.
- m1 (Monotone & Gradient Shaping): fix insensitivity/saturation; use stable smooth functions (e.g., softplus/logsigmoid/log1p) to shape gradients.
- m2 (Affine/Scale Invariance Fix): avoid raw objective units; prefer dimensionless signals (delta_z/delta_rank/delta_regret or normalized gaps).

Hard constraints:
- Output must be a SINGLE JSON object (no Markdown, no extra text).
- Must include fields: "strategy", "reasoning_brief", "expects", "code".
- "strategy" must match the given STRATEGY.
- "reasoning_brief" must be <= 80 words.
- "expects" must be a JSON array of input key strings (from CONTRACT_JSON.allowed_keys only).
- "code" must define exactly one function:
  def generated_loss(batch, model_output, extra):
    ...
  returning a scalar torch.Tensor (use .mean()).
- No imports. No filesystem/network. No external variables. Do not access builtins.
- Use only the allowed keys from CONTRACT_JSON.allowed_keys.
  - If the loss is pairwise: read inputs from batch[...] only.
  - If setwise: read inputs from model_output[...] only.
- Numerically stable: avoid NaN/Inf; clamp denominators with eps; avoid exp overflow; avoid huge slopes.

Output JSON schema (required fields):
{
  "strategy": "e1|e2|m1|m2",
  "reasoning_brief": "...",
  "expects": ["..."],
  "code": "def generated_loss(batch, model_output, extra):\\n    ...\\n"
}
